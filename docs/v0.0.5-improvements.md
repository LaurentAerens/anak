## Detailed Step Logs

### Step 2.1: Best Move Stability Tracking in TimeManager
- **Date**: 2026-10-23
- **Files Modified**: `src/Anak.Search/Time/TimeManager.cs`, `src/Anak.Search/Minimax/AlphaBetaEngine.cs`
- **Description**:
  - Implemented move stability tracking across iterative deepening iterations in `TimeManager`.
  - When the root best move remains stable for $\ge 4$ depths, the soft time limit is scaled down to $0.8\times$ base to save clock.
  - When the best move flips late in search (depth $\ge 8$ with prior stability), time allocation is expanded up to $1.8\times$ (capped by hard time limit) to resolve positional ambiguity.
- **Match Results (Direct Head-to-Head vs Current `main`)**:
  - **Opponent**: `Anak main` (with Phase 1 Complete)
  - **Match Settings**: 250 games, TC: 3s + 0.05s, 16 threads, 64 MB Hash, `openings.epd`
  - **Score**: **132.5 / 250** (88 Wins, 73 Losses, 89 Draws) &rarr; **53.00%**
  - **Elo Difference**: **+20.87 &plusmn; 32.81**
  - **Likelihood of Superiority (LOS)**: **89.50%**
  - **PGN Archive**: `tools/fastchess/results/anak_dev_vs_main_20261023_215339.pgn`
- **Action**: **Accepted into `main`**.

## Detailed Step Logs

### Step 1.1 & 1.2: Improving Heuristic & Reverse Futility Pruning
- **Date**: 2026-10-23
- **Files Modified**: `src/Anak.Search/Minimax/AlphaBetaEngine.cs`
- **Description**:
  - Implemented the `improving` flag in search: a position is improving if the current static evaluation is greater than the static evaluation 2 plies ago (or 4 plies ago if ply-2 was in check).
  - Conditioned Reverse Futility Pruning on `improving`: when improving, `rfpMargin` is scaled by $1.3\times$, requiring a larger margin above beta before pruning.
- **Match Results**:
  - **Opponent**: Anak v0.0.4 Baseline (1678 Elo)
  - **Match Settings**: 250 games, TC: 3s + 0.05s, 16 threads, 64 MB Hash
  - **Score**: 133.5 / 250 (98 Wins, 81 Losses, 71 Draws) &rarr; 53.40%
  - **Elo Difference**: **+23.66 &plusmn; 36.09** (LOS: 90.21%)

### Step 1.3: Improving Heuristic in Null Move Pruning (NMP)
- **Date**: 2026-10-23
- **Files Modified**: `src/Anak.Search/Minimax/AlphaBetaEngine.cs`
- **Description**: Tested increasing null move reduction $R$ ($r{+}{+}$) when `improving == true`.
- **Match Results**:
  - **Opponent**: Anak v0.0.4 Baseline
  - **Score**: 119.5 / 250 (84 Wins, 95 Losses, 71 Draws) &rarr; 47.80% (-15.3 Elo)
- **Action**: **Reverted**. NMP already dynamically scales reduction via `(eval - beta) / 200`; additional reduction caused tactical over-pruning.
